## What

Issues #20 / #22 / #83 add a BIOS security advisory notice for the TPM 2.0 flaws
**CVE-2026-6726** and **CVE-2026-6727** to our 35 **AMD** review pages. That work
is scoped AMD-only.

**Intel is also listed as Affected for the same two CVEs**, and our 35 Intel
review pages currently carry nothing. This issue is to verify the Intel scope
and then close that gap.

The CERT/CC vulnerability note published alongside the AMD bulletin is the
umbrella record for both vendors:

- **VU#431093** — "TCG TPM 2.0 reference code found vulnerable to information
  leakage and timing side-channel attacks". Published **11 August 2026**,
  last updated 12 August 2026. CVEs: CVE-2026-6726, CVE-2026-6727.
  Vendor status list: **Affected — AMD, Intel.** Not Affected — Absolute
  Software, Ampere Computing, libtpms (IBM sponsored), Meta. All other
  vendors listed as Unknown.
- Intel's own advisories: **INTEL-SA-01372** (CVE-2026-6726, incorrect type
  conversion or cast) and **INTEL-SA-01371** (CVE-2026-6727, observable timing
  discrepancy), both covering Intel CSME and Intel SPS firmware.

The root cause is identical to the AMD case and is not an AMD bug: the flaw is
in the Trusted Computing Group's TPM 2.0 **reference code** (TCG advisory
TCGVRT0010, "TPM 2.0 Improper Object Slot Reuse", released 11 August 2026).
AMD ships that reference code as fTPM; Intel ships it as **PTT (Platform Trust
Technology)**. Both were found by Intel researchers.

Same framing as #22 applies and should be reused verbatim in spirit: **this is
not a recall and not remotely exploitable.** Both CVEs require local access with
already-elevated privileges. The honest reader takeaway is "update your BIOS
when convenient," not "your board is unsafe."

## Why

Reader protection. A reader on our Z890 or B760 board pages gets no signal that
a firmware fix exists, while a reader on the equivalent AMD page (once #20/#22
land) does. Leaving half the catalogue advised and half silent is worse than
either extreme, because it implies by omission that Intel boards are unaffected.

Verified against the tree on 2026-08-21: `grep -licE 'advisory|CVE-' review-*.html`
returns 0 — no review page mentions any security advisory yet.

## Why needs-plan, not agent-ok

Two CLAUDE.md tripwires fire and one spec question is genuinely open:

1. **Scope is 35 files** (>15-file tripwire).
2. **The affected Intel CPU range is not yet confirmed from a primary source.**
   heise (12 August 2026) reports Intel's affected parts as "desktop, notebook,
   and embedded processors **up to and including the Core Ultra 200 series**",
   plus Xeon Scalable up to 3rd-gen (Ice Lake). If accurate that covers both of
   our Intel sockets — LGA1700 (12th/13th/14th Gen, Z790/B760) and LGA1851
   (Core Ultra 200S, Z890/B860). **This must be confirmed against
   INTEL-SA-01371/01372 themselves before any copy is written.** Per CLAUDE.md
   rule 1, do not publish a CPU-generation scope taken from press coverage.
3. **We do not know which boards have a fixed BIOS.** Unlike AMD, no public
   per-platform firmware-version table has been found for the Intel side. heise
   reports only that Intel "distributed new firmware versions to manufacturers
   ... who will offer corresponding BIOS updates over the next weeks and
   months." If a board has no fixed BIOS yet, the notice must say so honestly
   rather than tell a reader to update to something that does not exist.

## Verification caveat — read before writing copy

The scout **could not load intel.com** (both INTEL-SA advisory URLs returned
HTTP 403). Everything attributed to INTEL-SA-01371/01372 above comes from
search-result summaries and secondary press, **not** from the advisories
themselves. VU#431093 and the NVD entries were read directly and are reliable.

Whoever implements this must open both INTEL-SA advisories and confirm the CVE
mapping, the affected product list and the recommended action before anything
goes on a page. If Intel's advisory contradicts anything above, Intel wins.
