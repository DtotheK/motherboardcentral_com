## Blocker 1 — no "Updated" date exists on any of the 35 pages

> - [ ] Per CLAUDE.md rule 5, only bump the page "Updated" date because the advisory is genuine new content.

There is nothing to bump. Across all 35 pages there is no `Updated` string, no `<time>` element, no `datetime=` attribute, and no published/modified date of any kind. The only date on a review page is the footer copyright (`© 2026 MotherboardCentral.com`).

So this AC implies adding a per-page Updated date line that does not exist today — new page furniture on 35 pages. That is a separate design decision (format, placement, whether it becomes a site-wide convention for the other 35 non-AMD review pages too, and whether it needs `dateModified` schema markup). Please split that out or specify it.

## Blocker 2 — no advisory/notice component exists

The site has `.info-box`, `.info-box.warning` and `.info-box.tip` in `css/style.css:1063-1093`. But on review pages `info-box warning` is already in use as the **Cons** box:

```html
<div class="info-box warning">
  <h3 style="color:var(--accent-orange);margin-bottom:0.75rem;">Cons</h3>
```

Reusing it for a security advisory would put two visually identical orange boxes on the same page meaning different things. So this needs either a new `.info-box.advisory` variant or a new component — i.e. new shared presentational CSS/markup repeated across 35 pages, which is the shared-template tripwire the issue itself flags.

Decisions needed: new CSS class or reuse; heading text; placement (above `<h1>`, directly after `<h1>`, after the intro, or above the spec table); and whether it is dismissible/static.

## Blocker 3 — "vendor BIOS support page for that specific board" — we have none

> - [ ] Links to the vendor BIOS support page for that specific board where we already have it; otherwise the vendor's general support site.
