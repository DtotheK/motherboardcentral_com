## What this is

A new guide page covering when a BIOS update is actually warranted, how to flash from inside the firmware, and how to flash with no CPU installed. Nine H2 sections, following the outline in the issue.

## Sourcing — the part that matters

This page can get someone's board bricked, so every per-vendor filename, USB format and button behaviour was checked against the vendor's own source, and only stated where that check succeeded.

**Confirmed at the vendor's own page:**

- **ASUS** — [USB BIOS FlashBack FAQ 1038568](https://www.asus.com/support/faq/1038568/): "a single sector USB flash drive in FAT16 / 32 MBR format", the `.CAP` file and the BIOSRenamer tool, root-directory placement, the three-second press and three-blink start signal, the five-seconds-then-solid failure signal, the eight-minute ceiling, and the verbatim warning "Please do not remove the USB flash drive, unplug the power supply, turn on the power or press the CLR_CMOS button during the execution." [FAQ 1053582](https://www.asus.com/us/support/faq/1053582/) is cited for the models that take `.AS` instead of `.CAP`.
- **MSI** — MSI's own [BIOS user guide PDF](https://download-2.msi.com/archive/mnu_exe/mb/Intel600BIOS.pdf): rename to `MSI.ROM`, save to the root of the drive, connect both power connectors ("No need to install CPU and memory"), use the Flash BIOS Port on the rear I/O, LED flashes while running and turns off when complete. The M-FLASH sequence comes from the same document.
- **Microsoft** — the BitLocker warning is sourced to [Microsoft's recovery documentation](https://learn.microsoft.com/en-us/windows/security/operating-system-security/data-protection/bitlocker/recovery-overview), which lists "upgrading critical early startup components, such as a BIOS or UEFI firmware upgrade" as a recovery trigger and recommends suspending protection for a planned update.

**Not confirmed — so not stated:**

- **GIGABYTE** — gigabyte.com returns 403 to automated retrieval, and the naming rule has changed across board generations (newer downloads ship a rename utility rather than expecting a fixed name). The page prints **no** GIGABYTE filename and sends the reader to their board's own support page.
- **ASRock** — the Instant Flash and BIOS Flashback procedures are published as image-only PDFs whose text could not be read at the source. Same treatment: no filename printed, reader sent to their board's own support page.

A test enforces both halves of this: a rename rule may only appear in a section that links the vendor page it came from, and the two unconfirmed vendors must point at the reader's own board page. That test caught the MSI rename rule being stated without its citation, which is now fixed.

No AGESA or BIOS version string appears anywhere, per the conflict flagged in #20. No hands-on or test claim is made.
