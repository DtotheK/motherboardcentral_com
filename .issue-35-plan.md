# DECISIONS

**D1 — How many boards, and which ones? → Four, all ASUS, listed below.**
Rule 1 says specs come from the manufacturer's spec page. ASUS is the only one
of the four vendors whose spec pages we can actually read. I verified all four
pages load and return real spec tables (fetched today):

| # | Board (house style) | Form factor | Manufacturer spec page |
|---|---|---|---|
| 1 | ASUS TUF Gaming B850-Plus WiFi | ATX | https://www.asus.com/us/motherboards-components/motherboards/tuf-gaming/tuf-gaming-b850-plus-wifi/techspec/ |
| 2 | ASUS ROG Strix B850-E Gaming WiFi | ATX | https://rog.asus.com/us/motherboards/rog-strix/rog-strix-b850-e-gaming-wifi/spec/ |
| 3 | ASUS TUF Gaming B850M-Plus WiFi | Micro-ATX | https://www.asus.com/us/motherboards-components/motherboards/tuf-gaming/tuf-gaming-b850m-plus-wifi/techspec/ |
| 4 | ASUS ROG Strix B850-I Gaming WiFi | Mini-ITX | https://rog.asus.com/us/motherboards/rog-strix/rog-strix-b850-i-gaming-wifi/spec/ |

Chosen to span tiers and form factors (mainstream ATX → enthusiast ATX → mATX →
ITX) rather than to stack one family. They also happen to differ from each other
on exactly the specs the issue says must never be stated as blanket B850 claims
— see D6.

**D2 — MSI / GIGABYTE / ASRock B850 boards? → Not in this issue. Follow-up.**
The MSI MAG B850 Tomahawk family is the single highest-demand B850 search term,
so leaving it out is a real cost. It is still the right call: with no readable
first-party spec source, the only way to publish those pages is to take specs
from retailers or third-party articles, which rule 1 forbids. Open a follow-up
issue (draft title: *"B850 batch 2: MSI / GIGABYTE / ASRock — blocked on a
first-party spec source"*) that records the 403s above and asks a human for a
route (allow-list `curl`, paste the spec tables into the issue, or approve a
named non-vendor source).

**D3 — Does B840 get coverage? → No, not in any form, not even a passing
mention.** It is a genuinely lower tier that does not merit review pages, and
one sentence about it would collide with live copy: `guide-sockets.html:259`
states "**all chipsets except A620 support CPU overclocking**", which B840
breaks. Fixing that sentence is a guide edit on a page this issue does not own,
and the underlying claim is not first-party verified here (AMD's own chipset
page is unreachable from this environment). Flagged in CAUTIONS.

**D4 — Amazon links? → Direct `/dp/` links, or no link at all. Never `/s?k=`.**
Rule 3 plus `scripts/validate.mjs` `checkAffiliate` — a search URL on a new page
is a **NEW** violation and fails the build; it cannot be baselined away. I
confirmed the conversion recipe in `docs/affiliate-asins.md` is executable here:
`WebSearch` restricted to `amazon.com` surfaces `/dp/` URLs (e.g. board 1 →
`B0DPLPLR88`), and a live fetch of `https://www.amazon.com/dp/<ASIN>` returns a
real product page. Amazon's own `/s?k=` search page returns nothing, so ASIN
discovery must go through `WebSearch`. Any board that fails one of the four
recipe tests ships **with no Amazon button anywhere on the page or its card**
and gets a row in the "Unconverted" section of the ledger.

**D5 — Vendor PDF datasheets as a fallback source? → Rejected, tested.**
I downloaded MSI's own B850 Tomahawk datasheet PDF and ran a stream-inflating
text extractor over it: 469,211 characters came out, and `B850`, `PCIe`, `M.2`,
`SATA`, `Wi-Fi` and `LAN` all matched **zero** times — the fonts are
glyph-subset encoded, so recovering text needs a ToUnicode CMap parser. `Read`
cannot render PDFs either (no `poppler-utils` installed). Do not spend worker
time on this route.

**D6 — Chipset-level claims. → Stated per board, from that board's page only.**
The four boards genuinely disagree with each other, which is the whole point of
the issue's second acceptance criterion. From the pages I fetched today:
Wi-Fi 7 on boards 1/2/4 but **Wi-Fi 6E** on board 3; 2.5Gb Ethernet on 1/3/4 but
**5Gb** on board 2; 4 SATA on 1/2/3 but **2** on board 4; a rear **USB4 40Gbps
port on board 2 only**, while board 1 has USB4 as an *internal header* and is
not a rear port. No page may say "B850 boards have…" — write "this board has…".
The PCIe 5.0 x16 slot is CPU-conditional on all four (5.0 with Ryzen 9000/7000,
4.0 with Ryzen 8000); write that condition into the spec row, do not flatten it.

**D7 — Star ratings and `Review`/`aggregateRating` JSON-LD? → Omitted on these
four pages.** The existing template hard-codes a 4.5/5 score and a schema.org
`Review` by MotherboardCentral. We have not handled these boards; a numeric
verdict we did not earn is precisely the trust leak rule 2 exists to stop. New
pages keep `@type: Product` and drop `review` + `aggregateRating`; the
`★★★★☆ 4.5/5.0` block under the hero image is dropped; the `reviews.html` cards
omit `.card-rating`. Cost: four cards in the grid will sit slightly higher than
their neighbours. Accepted deliberately — flagged for a human glance.

**D8 — "Video Review" section? → Omitted.** The template embeds a YouTube ID.
We have no verified video for any of these four boards, and an embed that turns
out to be a different board is a spec-accuracy failure with our name on it.

**D9 — Hero / card images? → Omitted; no `<img>` for these boards.** We have no
licensed shot and must not invent one, and pointing at a non-existent
`images/reviews/*.jpg` is a `broken-link` violation. Precedent exists:
`preview-gigabyte-b550-x-series.html` ships with no images, and the card for it
in `guides.html` has no `.card-img`. Do the same here.

**D10 — `data-price` on the new `reviews.html` cards? → Omit the attribute.**
Rule "never invent prices" outranks filter tidiness, and Amazon's terms stop us
publishing a static price anyway. Known consequence: `js/main.js` does
`parseFloat(card.dataset.price) || 0`, so a card with no price counts as `$0`
and will appear under "Under $150". Do **not** patch `main.js` in this PR — that
is shared site JS and trips the tripwire. Record the quirk in the PR body and in
the follow-up issue.

**D11 — Cons lists. → Every new page ships at least two real, spec-derived
cons.** Issue #41 exists because 32 pages have an empty Cons box; do not add
four more. Cons must be traceable limitations, not padding — e.g. board 4: two
SATA ports and two M.2 slots only; board 3: Wi-Fi 6E while its siblings are
Wi-Fi 7; boards 1/3/4: no rear USB4 port. Keep the surrounding markup **byte-
identical** to the existing template (`grid-template-columns:1fr 1fr`) so #41's
mobile-stacking fix lands everywhere at once; do not invent a one-off responsive
variant here.

**D12 — Slugs and naming.** Slugs are permanent (no redirect layer in this
repo), so fix them now:
`review-asus-tuf-gaming-b850-plus-wifi.html`,
`review-asus-rog-strix-b850-e-gaming-wifi.html`,
`review-asus-tuf-gaming-b850m-plus-wifi.html`,
`review-asus-rog-strix-b850-i-gaming-wifi.html`.
Display names use house title case ("ASUS ROG Strix B850-E Gaming WiFi"), not
ASUS's all-caps, matching every existing page.

**D13 — Which existing files get touched? → `reviews.html`, `sitemap.xml`,
`docs/affiliate-asins.md`. Nothing else.** No edits to `index.html`, to
`guide-sockets.html`, or to any existing review page (back-links from 30+ pages
would blow the 15-file tripwire). Cross-linking is one-directional: the new
pages link out to existing AM5 boards from their "Related Boards" grid.

**D14 — A B850 chipset explainer page? → No.** That is issue #37's scope
(chipset comparison tables). Duplicating it here would create exactly the
cross-page contradiction risk rule 1 forbids.

Total: **7 files changed, 4 new pages.** Under the tripwire. One PR.

# CAUTIONS

- **All four boards are ASUS.** That is a real editorial skew and it under-serves
  the "B850 Tomahawk review" demand the issue names. It is a consequence of the
  403 table, not an editorial preference. If a human can unblock MSI/GIGABYTE/
  ASRock fetching, batch 2 should follow immediately.
- **`guide-sockets.html:259` is now wrong-ish and out of scope.** "All chipsets
  except A620 support CPU overclocking" does not hold once B840 exists, and that
  page's AM5 chipset table still lists only X670E/X670/B650E/B650/A620 — it has
  no 800-series row at all, despite the site reviewing X870/X870E boards. Both
  belong to issue #37. I have not verified B840's overclocking status against
  AMD directly (amd.com is unreachable from here); it is widely reported but
  treat it as unverified.
- **`WebSearch` summaries are not a spec source, demonstrated.** A domain-
  restricted search for the Prime B850M-A returned "PCIe 4.0 x16" and "PCIe 5.0
  x16 slot" in the same summary, and a B850/B840 query returned a sentence that
  contradicted itself on PCIe 5.0 graphics. Use search only to find a URL or an
  ASIN, never to fill a table cell.
- **Model-name collisions are live in this family.** MSI ships B850 Tomahawk
  *WIFI*, *MAX WIFI*, and *MAX WIFI II*; GIGABYTE ships B850 AORUS Elite WIFI7
  and a WIFI7 *ICE*; ASUS ships TUF Gaming B850M-Plus **WIFI** (Wi-Fi 6E) and
  TUF Gaming B850M-Plus **WIFI7** (Wi-Fi 7) — two different boards one character
  apart, and board 3 is the former. There is also a Prime B850M-A WiFi-**CSM**
  commercial variant. Any ASIN or spec mixed across these is a rule-1 breach.
- **D7 leaves the reviews grid visually ragged** — four cards with no image and
  no star row. Worth a human glance to confirm that honesty-over-uniformity is
  the wanted trade here; if not, say so and the worker can add a neutral
  "specifications only" label instead of a score.
- **D10's price quirk is a real, visible inaccuracy**: the four new boards will
  show up under "Under $150" in the price filter until `js/main.js` learns to
  treat a missing price as unknown. I chose that over inventing prices.
- **Board 2's 5Gb LAN is unusual for the tier.** It came straight off ROG's spec
  page today, and it is the kind of spec a reader will challenge. Quote it
  exactly and keep the prose consistent with it.
