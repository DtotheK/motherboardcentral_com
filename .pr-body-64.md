Adds hover / tap / keyboard definitions for spec-table jargon, implemented entirely in `js/main.js` + `css/style.css`. No HTML page was edited.

## What it does

At runtime, `MBCGlossary` scans plain-text cells in `.spec-table`, `.compare-table` and `.compare-table-wrap` and wraps the first occurrence of each known term in a focusable `<button class="glossary-term">` with a `role="tooltip"` definition wired up via `aria-describedby`. Terms get a dotted underline; the definition opens on mouse hover, on tap, and on keyboard focus, and closes on Esc, on tap-away, or when focus leaves.

Because spec tables set `overflow: hidden`, the tooltip is `position: fixed` and placed from JS (`tipPosition`), clamped to the viewport and flipped above the term when there is no room below.

A `MutationObserver` re-runs the pass after DOM changes, so `compare.html`'s JS-rendered table is covered as well as the static review tables.

## Terms

All 10 from the issue: power phases, VRM, ALC audio codecs, PCIe, M.2, WiFi, Bluetooth, LAN speed, EXPO/XMP, form factor (ATX / Micro-ATX / Mini-ITX), DDR4/DDR5.

Definitions are conceptual only — no claim about any specific board, so nothing here can contradict a spec elsewhere. Figures used in the definitions (ATX 305 x 244mm, Micro-ATX 244 x 244mm, Mini-ITX 170 x 170mm, DDR4/DDR5 slot incompatibility, PCIe bandwidth doubling per generation) were taken from our own guides so the tooltips and the guides agree.

Ten of the fourteen dictionary entries end with a link to the matching guide (`guide-cooling.html#vrm-heatsinks`, `guide-pcie.html#what-is-pcie`, `guide-storage.html#m2-nvme`, `guide-ram.html#xmp-expo`, `guide-ram.html#ddr4-vs-ddr5`, `guide-cases.html#atx` / `#micro-atx` / `#mini-itx`). The four with no matching guide — ALC codecs, WiFi, Bluetooth, LAN speed — carry no link.

## Flagged for review

1. **Not verified in a browser.** There is no browser or DOM library in this environment, so the tooltip's appearance, placement and touch behaviour were verified by unit tests against a stub DOM and by reading the CSS — not by rendering a page. The "does not look noisy" criterion is the one that really wants human eyes.
2. **Two terms in the issue's list never appear inside a spec table on a review page.** The issue lists VRM ("VRM & Power Delivery section") and EXPO/XMP ("Build Tips") — both live in prose, not in a table cell, and the issue's implementation scope is explicitly `.spec-table` / `.compare-table` cells. They are in the dictionary and do fire where they occur in a table cell (VRM appears in the budget tables on the `best-motherboard-for-*` pages), but on a standard review page neither will show. Widening the scope to prose would be a bigger change than the issue specifies, so it was left alone — worth a follow-up issue if the tooltips are wanted there.
3. **Site-wide asset change.** `js/main.js` and `css/style.css` load on all 95 pages. That is not "template, nav, footer or layout markup" under the letter of the CLAUDE.md tripwire, but the blast radius is the whole site and point 1 above means the visual result is unverified, so this PR is labelled `needs-human` and auto-merge is **not** enabled.
