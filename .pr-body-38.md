## Slug scheme

Slugs come from the board name, never from its index in `motherboardDatabase`:

```
lowercase -> drop "." -> "+" becomes " plus " -> non-alphanumerics collapse to "-"
```

So `ASRock A620M-HDV/M.2+` → `asrock-a620m-hdv-m2-plus`, which is exactly `review-asrock-a620m-hdv-m2-plus.html`. A test asserts this for **all 69 boards** in the database: every slug is the filename of that board's published review page, so the slug is already reusable for the cross-linking work the issue anticipates.

Extra guards, since `js/main.js` loads on every page:

- `pages without a comparison table never touch the URL` — boots `index.html` with `?boards=nonsense` in the query string and asserts zero `replaceState` calls.
- `the compare page still works where history.replaceState is unavailable` — the feature-detect degrades to today's behaviour.
- `the URL round-trips: what a change writes, a fresh load reads back`, `other query parameters survive a selection change` (a `?utm_source=` is preserved), and `a stale ?boards= is replaced, not appended to`.
- `commas in the shared link are left literal, not percent-encoded` — the param is appended raw rather than through `URLSearchParams.toString()`, which would emit `%2C` and make shared links unreadable.

## Notes on two judgement calls the issue left implicit

1. **A repeated slug becomes an empty slot**, per the acceptance criteria. The dropdowns themselves still let you put the same board in two slots; if you do, the URL records it and a reload collapses the second column to empty. Following the stated criterion rather than round-trip symmetry.
2. **Trailing empty slots are dropped from the URL** (`a,` → `a`) but interior ones are kept (`,b` stays `,b`), so a board never jumps columns on reload while shared links stay short.
